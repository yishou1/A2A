# 算法管理界面功能说明

## 1. 文档说明

| 项目 | 内容 |
|---|---|
| 文档名称 | 算法管理界面功能说明 |
| 适用项目 | A2A 算法库 |
| 编制日期 | 2026-08-21 |
| 文档用途 | 说明算法管理界面的建设内容和使用方式 |

## 2. 建设目标

算法管理界面面向算法库的日常使用和维护，提供统一、直观的可视化操作入口，将原来分散的算法查看、状态维护、部署管理和调用验证工作集中到同一界面中完成。

通过本界面，使用人员可以清楚了解：

- 当前算法库中有哪些算法。
- 每个算法能够完成什么任务。
- 算法当前是否已经验证、激活和就绪。
- 算法部署在哪些运行节点，是否已经加载并具备运行条件。
- 算法是否能够正常接收输入并返回结果。
- 算法对应哪些 A2A 业务功能，执行过程是否成功。

界面形成“**算法纳管、状态控制、部署管理、在线验证、过程查询**”的完整管理闭环。

## 3. 整体功能

算法管理界面包括以下主要功能：

| 序号 | 功能模块 | 主要作用 |
|---:|---|---|
| 1 | 运行总览 | 集中查看算法库整体运行和算法状态 |
| 2 | 算法目录 | 查询、搜索和筛选已有算法 |
| 3 | 算法详情 | 查看算法用途、输入输出、性能和资源信息 |
| 4 | 算法纳管 | 将新的算法包登记到算法库 |
| 5 | 状态管理 | 完成验证、激活、禁用和删除操作 |
| 6 | 部署管理 | 管理算法部署节点、部署记录以及加载和卸载状态 |
| 7 | 在线验证 | 在界面中输入测试数据并查看算法结果 |
| 8 | 功能点映射 | 查看算法与 A2A 业务功能的对应关系 |
| 9 | 执行链路查询 | 根据任务标识查看算法执行过程 |

## 4. 运行总览

运行总览用于快速掌握算法库整体情况，是进入系统后的首个页面。

主要展示内容包括：

- 算法总数。
- 已激活、已验证、已禁用和待完善的算法数量。
- 已就绪、未加载和异常的部署实例数量。
- 不同算法运行方式的数量分布。
- 当前算法库服务是否正常。
- 当前已加载的算法运行实例数量。
- 需要关注的算法，例如已激活但尚未部署、部署未就绪、加载失败或资料尚未完成验证的算法。

通过总览页面，可以在不逐个查看算法的情况下，快速判断算法库是否处于正常运行状态，并定位需要进一步处理的问题。

## 5. 算法目录

算法目录以统一列表展示算法库中的全部有效算法。

### 5.1 列表信息

每个算法主要展示：

- 算法名称和算法编号。
- 当前版本。
- 算法类型和所属任务类别。
- 当前管理状态。
- 部署实例数量和就绪情况。
- 算法具备的主要能力。
- 主要性能指标和资源需求。

### 5.2 查询与筛选

支持通过以下条件快速查找算法：

- 按算法名称或编号搜索。
- 按算法状态筛选。
- 按任务类别筛选。
- 按算法能力筛选。
- 按运行方式筛选。
- 按所支持的业务功能点筛选。
- 按部署节点和部署状态筛选。
- 按计算资源条件筛选。

例如，可以快速查询“当前已经激活的目标识别算法”“支持某项业务功能的算法”或“能够在指定资源条件下运行的算法”。

### 5.3 快捷操作

列表中根据算法当前状态提供相应操作：

- 待验证算法可以进行验证。
- 已验证算法可以进行激活。
- 已激活算法可以直接进入在线验证。
- 已激活算法可以暂停使用。
- 已停用算法可以重新激活。
- 不再使用的算法可以进行删除。

界面只展示当前状态下允许执行的操作，减少错误操作。

## 6. 算法详情

算法详情页用于全面了解单个算法的能力和当前情况。

### 6.1 基本信息

展示算法名称、版本、用途说明、所属任务类别、当前状态以及适用和不适用场景。

### 6.2 能力说明

展示算法可以完成的主要任务、支持的数据类型以及与其他算法的能力差异，便于使用人员判断是否适合当前业务场景。

### 6.3 输入输出说明

展示算法需要哪些输入、各项输入的含义、是否必填，以及算法会返回哪些结果。对于复杂数据，可同时查看输入输出示例。

### 6.4 性能与资源

展示算法已登记的主要性能指标、参考处理时延、模型规模以及运行所需的处理器、内存和显存等资源条件。

这些信息可以用于算法选型和部署资源规划，但界面会区分“登记指标”和“当前实际运行状态”，避免将参考指标理解为实时监测结果。

### 6.5 业务功能关联

展示算法支持的 A2A 业务功能，以及算法在该功能中的作用和覆盖程度，便于从业务任务反向查找可用算法。

### 6.6 部署情况

展示算法在各运行节点上的部署记录、加载状态、服务位置和最近更新时间，以便判断算法是否已经具备运行条件。

## 7. 算法纳管

算法纳管用于将新的算法包登记到算法库中。

支持选择算法库中已经准备好的算法包，并由系统自动检查算法资料是否完整，包括算法基本信息、输入输出定义、运行配置和必要文件等。

纳管结果分为：

- **纳管成功**：算法进入“已验证”状态，可继续进行激活和部署操作。
- **纳管失败**：界面明确展示问题原因，使用人员修正算法资料后可重新操作。

算法纳管成功后不会立即对外提供服务，需要由使用人员进一步确认并执行激活，避免未经确认的算法直接进入业务调用范围。

当前从算法库中已经准备好的算法包进行纳管。

## 8. 算法状态管理

界面提供算法从登记到退出使用的全过程状态管理。

### 8.1 状态说明

| 界面状态 | 含义 |
|---|---|
| 草稿 | 算法已登记，但资料尚未完成验证 |
| 已验证 | 算法资料检查通过，但尚未允许业务调用 |
| 已激活 | 算法已经进入可调用范围 |
| 已禁用 | 算法资料保留，但暂时停止新的统一调用 |
| 已删除 | 算法已从常规管理范围移除 |

### 8.2 验证

验证用于检查或重新检查算法资料。算法资料更新后，可通过“重新验证”刷新界面中展示的能力、输入输出和资源信息。

验证通过表示算法资料符合纳管要求，不代表模型已经部署或加载。界面会分别展示资料状态、部署状态和运行状态。

### 8.3 激活

激活用于将已验证或已停用的算法加入可调用范围。激活前，界面会提示确认算法模型、运行服务和部署条件是否已经准备完成。

### 8.4 禁用

禁用用于暂停算法的新调用请求，同时保留算法资料和部署记录，后续可以重新激活。

禁用不会自动卸载模型。使用人员可以根据实际需要选择是否继续执行卸载操作。

### 8.5 删除

删除用于将不再使用的算法移出常规算法目录。

删除前，界面会检查算法是否仍处于激活或加载状态，并提示先完成禁用和卸载。删除操作需要二次确认，防止误操作。

删除为管理层面的逻辑删除，不会直接删除服务器中的算法原始文件。

## 9. 算法信息更新

支持在算法资料发生变化后执行“重新验证”，由系统重新读取并刷新算法说明、能力、输入输出和资源信息，同时保留已有部署记录。

算法编号、版本和运行方式共同确定一个独立算法项。如这些关键信息发生变化，应作为新的算法版本或新的算法项进行纳管，而不是直接覆盖原有记录，以便保留清晰的版本关系。

当前不在网页中直接修改算法源文件和模型文件，避免线上内容与算法包原始资料不一致。

## 10. 部署管理

部署管理用于查看和维护算法在不同运行节点上的部署情况，并根据使用需要加载或释放算法运行资源。

### 10.1 部署实例管理

同一个算法可以登记一个或多个部署实例。每个部署实例对应算法在一个运行节点上的部署记录，主要包括部署标识、节点、区域、服务位置、模型位置、当前状态和更新时间。

界面支持：

- 新增部署实例。
- 查看部署节点和服务位置。
- 查看部署是否已经就绪。
- 维护部署状态和状态说明。
- 删除不再使用的部署记录。

部署状态包括：

- **未加载**：已经登记部署记录，但尚未准备运行资源。
- **加载中**：正在传输或加载模型和配置。
- **已就绪**：加载完成，可以接收算法调用。
- **异常**：部署或加载失败，界面展示具体原因。

删除部署记录只移除算法库中的登记信息，不等同于停止运行服务或删除模型文件。对于已加载的部署，应先卸载，再删除部署记录。

### 10.2 模型分发与远程部署

算法库支持由目标运行节点按需拉取算法模型及配套配置，并在目标节点建立算法运行实例。模型文件来源、目标保存位置和需要获取的文件可以按部署任务进行设置。

模型拉取和初始化过程中，部署状态依次显示为“加载中、已就绪或异常”，相关结果同步回写到部署记录中。

这里的远程部署是指：目标节点已经运行算法库服务，并通过算法库提供的模型拉取和加载能力完成部署。界面负责下发部署参数、展示过程和维护状态。

以下内容不属于本界面直接完成的范围：

- 自动安装或初始化一台全新的服务器。
- 自动创建操作系统、容器或计算集群。
- 自动申请云资源或完成网络环境配置。

### 10.3 预加载算法

预加载用于提前将算法模型和运行资源准备到可使用状态，从而减少首次调用的等待时间。

算法激活后已经具备调用资格；预加载是可选操作。如果未提前加载，系统可在首次调用时自动完成加载。重复预加载同一个已经就绪的实例时，系统不会重复创建运行资源，避免不必要的资源占用。

### 10.4 卸载算法

卸载用于释放指定部署实例占用的运行资源。卸载完成后，算法资料和部署记录仍然保留，相应部署实例显示为“未加载”。

禁用和卸载是两个不同操作：

- 禁用控制算法是否允许接收新的统一调用。
- 卸载控制部署实例是否继续占用运行资源。

界面会分别展示并管理这两种状态。

## 11. 在线验证

在线验证用于确认已激活算法能否按照约定接收输入并返回结果。

### 11.1 输入方式

界面根据算法的输入要求自动生成测试表单，使用人员可以直接填写数据。对于结构较复杂的算法，也提供完整数据编辑方式。

### 11.2 部署选择

当算法存在多个已就绪部署实例时，可以选择指定实例进行在线验证；未指定时，由系统选择可用的运行实例。

### 11.3 结果展示

调用完成后展示：

- 调用是否成功。
- 算法输出结果。
- 本次处理耗时。
- 实际使用的算法版本和运行方式。
- 本次任务和链路标识。
- 失败时的错误原因和处理提示。
- 对应的业务功能执行情况。

在线验证主要用于算法接入确认、运行检查和问题定位，不替代正式业务系统中的批量任务执行。

## 12. 业务功能点映射

功能点矩阵用于展示 A2A 业务功能与算法之间的对应关系。

使用人员可以：

- 查看每个业务功能由哪些算法提供支持。
- 查看算法在业务功能中承担主要处理、辅助处理或流程组织等作用。
- 查看算法对业务功能是完整覆盖、部分覆盖还是仅提供建议。
- 查看关联算法是否已经激活以及是否存在已就绪部署。
- 从业务功能直接进入相关算法详情。

该功能有助于从业务视角检查算法能力覆盖情况，并为任务编排和算法选型提供依据。

## 13. 执行链路查询

执行链路查询用于根据任务链路标识查看相关算法的执行过程。

界面按照执行顺序展示：

- 执行的业务功能。
- 使用的算法及版本。
- 执行成功或失败状态。
- 单步处理耗时。
- 失败时的错误信息。
- 各算法在本次流程中的执行顺序。

支持根据已知链路标识进行查询，主要用于任务联调和问题定位。

## 14. 操作保护与信息安全

界面提供以下基础保护措施：

- 删除、禁用、卸载和删除部署记录等操作均进行二次确认。
- 删除前明确展示算法名称、版本以及操作影响。
- 算法库服务不可用时停止提交变更操作，避免界面状态与实际状态不一致。
- 算法和模型文件的访问范围由系统进行边界检查。
- 在线验证的完整输入输出默认不在浏览器中长期保存。
- 操作失败时保留当前页面信息，并给出明确原因，不产生无提示的状态变化。

## 15. 功能范围

### 15.1 包含功能

- 算法总览和状态统计。
- 算法目录、搜索、筛选和详情查询。
- 算法纳管和资料验证。
- 算法激活、禁用和逻辑删除。
- 部署实例新增、查看、状态维护和删除。
- 目标节点模型拉取和部署状态跟踪。
- 算法预加载和卸载。
- 算法在线验证及结果查看。
- 业务功能点与算法映射查询。
- 根据链路标识查看执行过程。

### 15.2 不包含功能

- 模型训练和训练任务管理。
- 数据采集、清洗和标注。
- 在网页中直接修改算法源文件或模型文件。
- 全量执行历史检索、趋势分析和统计报表。
- 复杂运行监控、告警和自动扩缩容。
- 新服务器操作系统和基础环境的自动安装。
- 容器集群创建、云资源申请和网络环境配置。

上述内容不影响算法纳管、部署、运行和验证等核心管理流程的使用。

## 16. 典型使用流程

### 16.1 新算法接入

```text
准备算法资料
  → 登记算法
  → 系统检查资料
  → 查看算法详情
  → 激活算法
  → 添加部署实例
  → 预加载算法
  → 在线验证
```

### 16.2 算法暂停与恢复

```text
选择已激活算法
  → 禁用算法
  → 根据需要卸载部署实例
  → 保留算法资料和部署记录
  → 需要恢复时重新激活并按需预加载
```

### 16.3 算法退出使用

```text
禁用算法
  → 卸载相关部署实例
  → 确认无继续使用需求
  → 二次确认删除
  → 算法退出常规目录
```

### 16.4 任务问题定位

```text
获取任务链路标识
  → 查询执行链路
  → 查看失败步骤和关联算法
  → 进入算法详情
  → 检查部署和加载状态
  → 使用在线验证复现问题
```

## 17. 建设效果

算法管理界面建成后，将形成以下能力：

1. **算法资产集中展示**：统一呈现算法名称、版本、能力、状态和部署情况。
2. **算法过程规范管理**：通过验证、激活、禁用和删除形成清晰的使用流程。
3. **运行状态直观可见**：区分算法是否允许调用、部署是否就绪以及模型是否已经加载。
4. **接入验证更加便捷**：无需使用命令操作，即可完成算法测试和结果查看。
5. **业务能力关系清晰**：能够从 A2A 功能点查看对应算法及其覆盖程度。
6. **问题定位效率提升**：可根据任务链路查看算法执行过程，并结合在线验证定位问题。
7. **误操作风险降低**：对禁用、卸载和删除等操作提供明确提示和二次确认。

## 18. 总结

算法管理界面围绕算法的完整使用过程进行建设，覆盖 **查看、纳管、验证、激活、部署、预加载、调用、禁用、卸载和删除** 等核心功能。

通过可视化界面，使用人员可以从算法资产和业务功能两个角度了解算法库现状，并完成算法接入、部署管理、运行验证和日常维护。界面重点保证管理流程完整、状态表达清楚和操作结果可追踪。
