## 2. 总体结论

当前前端已从页面原型进入真实业务开发阶段。项目已建立独立的 React + TypeScript + Vite 工程，完成统一管理框架、七个主要业务路由和后端 API 封装，并已接通真实 AlgoLib Server。

目前可以在界面中完成以下主流程：

1. 查看算法库运行状态和全部已纳管算法。
2. 通过服务器算法包路径注册算法。
3. 查看算法卡、输入输出 Schema、性能资源和功能点映射。
4. 执行验证、激活、禁用和逻辑删除等生命周期操作。
5. 登记部署、更新部署状态、加载、卸载和删除部署记录。
6. 根据 Schema 填写输入并在线调用已激活算法。
7. 查看 28 个 KC 功能点与算法的覆盖关系。
8. 根据 trace ID 查询算法执行链路。

当前版本适合继续进行真实算法联调、交互完善和验收测试，但尚不建议直接作为生产版本交付。主要差距集中在端到端自动化、异常场景覆盖、URL 状态保持、生产部署配置、权限安全和性能优化。

## 4. 功能开发现状

### 4.1 运行总览

已实现：

- 算法总数及 active、validated、disabled、draft 状态统计。
- 部署总数及 ready、unloaded、error 状态统计。
- 需处理算法数量汇总。
- 服务健康状态、Runner Cache、Registry 路径和执行日志路径展示。
- 服务不可达和数据加载失败提示。

待完善：

- ONNX/Python HTTP、任务族等分布图表。
- “需处理项”明细列表及快捷跳转。
- 断线后的最后成功数据保留、过期遮罩和统一变更禁用。
- 最后刷新时间展示。

### 4.2 算法目录与注册

已实现：

- 请求 `active_only=false`，显示 Registry 中全部非删除算法。
- 按算法名称或 ID 搜索。
- 按注册状态、后端类型筛选。
- 展示版本、任务族、部署就绪数和能力标签。
- 分页、空状态、错误状态和注册入口。
- 输入 AlgoLib Server 可访问的算法包目录或算法卡路径进行注册。
- 注册后刷新数据，并可自动进入算法详情页。

需要特别说明：当前注册方式是“服务器路径注册”，不是浏览器上传文件。服务器必须能够访问所填写的算法包目录。

待完善：

- 任务族、能力、KC 功能点、节点、部署状态和资源条件等高级筛选。
- 筛选、排序和分页写入 URL Query。
- 可选列、列宽偏好及批量操作。
- 算法包上传、预检、安全扫描不在当前后端能力范围内。

### 4.3 算法详情与生命周期

已实现：

- 展示算法唯一键、Registry 状态、算法卡状态和后端类型。
- 概览、输入输出、性能资源、功能点、部署实例、算法卡六个页签。
- 获取并显示完整 input/output Schema。
- 根据状态机显示验证、激活、禁用和删除操作。
- 禁用操作二次确认；逻辑删除要求输入算法 ID。
- active 算法可直接跳转在线调用。
- active 但没有 ready 部署时提示可能触发按需加载。

待完善：

- Schema 字段表格化展示，目前主要为格式化 JSON。
- 算法卡结构化视图与原始 JSON 双视图进一步细化。
- 性能数据图表及实时监控能力；当前明确展示的是算法卡登记值。
- 统一的操作审计信息和请求关联 ID 展示。

### 4.4 部署管理

已实现：

- 全局部署列表及算法详情内的部署面板。
- 按部署、节点、算法关键字搜索，按部署状态筛选。
- 新增部署实例，初始状态为 `unloaded`。
- ONNX 和 Python HTTP 分支化加载参数。
- 调用同步 `/load` 和 `/unload` 接口。
- 更新部署登记状态。
- ready 部署要求先卸载后删除，并提供二次确认和影响说明。
- 部署 ID 包含斜杠时能够正确调用后端路由。

待完善：

- 加载耗时较长时的任务化进度和取消能力。
- Runner 实际加载状态与部署登记状态的独立对账。
- 节点和外部 Python 服务健康状态实时检测。
- endpoint、node、zone 的编辑能力；当前采用删除后重建策略。

### 4.5 在线调用

已实现：

- 只选择 active 算法，支持由详情页携带算法参数进入。
- 根据完整 JSON Schema 生成基础输入表单。
- 支持 string、number、integer、boolean、enum、object 和 array。
- 支持 JSON 模式作为复杂输入的保底方式。
- 优先使用算法卡示例、Schema default/examples 初始化输入。
- 使用 AJV 在发起网络请求前校验 inputs。
- 支持选择 ready 部署、填写 params、功能上下文、Workflow ID 和 Step ID。
- 自动生成 request ID 和 trace ID。
- 调用请求不自动重试。
- 展示成功输出、usage、错误信息、function execution 和完整请求预览。
- 支持复制请求、响应和 trace ID，并可跳转执行链路页面。

待完善：

- JSON 编辑目前使用文本域，尚未接入动态加载的 Monaco Editor。
- 复杂 Schema 的 `oneOf`、`anyOf`、条件 Schema、文件等高级表单映射。
- 请求区和结果区拖动调整宽度。
- 大 JSON 虚拟化、折叠、搜索和差异查看。
- Python HTTP 算法的完整真实调用验收。
- 503、504、超时、输出 Schema 错误等异常矩阵验收。

### 4.7 执行链路

## 5. 前后端接口接入现状

前端当前已经封装并使用以下接口能力：

- 健康检查：`GET /health`
- 算法列表与详情：`GET /algorithms`、`GET /algorithms/{id}/{version}/{backend}`
- 完整 Schema：input/output Schema 查询
- 算法注册、验证、激活、禁用和逻辑删除
- 部署新增、状态更新和删除
- Runner 加载与卸载：`POST /load`、`POST /unload`
- 功能目录：`GET /operational-functions`
- 算法执行：`POST /run`
- 执行链路：按 trace ID 查询 function executions

算法三元组路径统一通过 `algorithmPath()` 生成并分别 URL 编码。API 错误由 `ApiError` 保留 HTTP 状态、业务错误码和原始响应数据。

开发环境使用 `/api` 反向代理，默认后端为 `http://127.0.0.1:8088`，也可以通过 `ALGOLIB_API_TARGET` 指定其他服务地址。

## 9. 主要问题与风险

### P0：进入正式验收前必须处理

1. 建立 Playwright E2E，覆盖注册、激活、部署、加载、调用、trace、禁用、卸载和删除主流程。
2. 补齐 Python HTTP 实际服务的在线调用和连接池场景验证。
3. 覆盖服务断开、400、409、422、503、504、超时和输出校验失败等异常场景。
