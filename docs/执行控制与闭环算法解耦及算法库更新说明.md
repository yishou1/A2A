# 执行控制与闭环评估算法解耦及算法库更新说明

## 1. 本次调整后的边界

代码现在分为两层：

1. `algorithmrepo/services/a2a_algorithms_common/` 是算法库主版本，内部只处理结构化输入、算法参数和结构化输出，不导入 Commander、Agent、A2A 通信或 FastAPI。
2. `commander/execution_control_agent/algolib_runtime.py` 与 `commander/closed_loop_agent/algolib_runtime.py` 是编排适配层，只负责收集前置 Agent 结果、选择算法档位、调用算法服务、检查返回契约和执行失败回退。

执行控制本地回退也已改为调用 `services.a2a_algorithms_common.execution_planner`，不再直接把 Agent 内部实现当作算法入口。Commander 中保留一份通用算法代码是为了离线回退；算法库目录是主版本，可通过 `scripts/check_zh_algorithm_vendor.ps1` 检查两份代码是否漂移。

## 2. 通用算法接口

所有算法服务使用同一形式：

```json
{
  "inputs": { "业务输入": "..." },
  "params": { "profile": "medium" }
}
```

支持 `low`、`medium`、`high`，并兼容 `small`、`large` 别名。非法档位会明确报错，不会静默套用默认值。未指定档位时使用 `medium`，保证与本次调整前的默认业务行为兼容。

## 3. 三档配置

| 档位 | 执行控制 | 任务完成度随机森林 | 适用场景 |
|---|---|---|---|
| `low` | 最多16条轨迹、3条规则；scikit-learn线性回归 | 使用32棵树 | CPU、边缘设备、低延迟演示 |
| `medium` | 完整输入；FilterPy常速度卡尔曼滤波 | 使用96棵树 | 默认部署，精度与速度平衡 |
| `high` | 完整输入；更低过程/观测噪声的FilterPy卡尔曼滤波 | 使用全部192棵树 | 数据质量较好的高精度部署 |

闭环决策建议器在三档下使用相同的 `standard_v1` 业务策略。它本身是常数时间阈值决策，没有值得削减的计算量；强行改变阈值会改变业务含义，因此档位只记录在输出和调用日志中，不改变决策条件。

当前任务完成度模型已经替换为 scikit-learn `RandomForestRegressor`，共192棵树。训练、验证和测试按 `replay_id` 做70%/15%/15%分组切分，同一场对局不会同时进入训练集和测试集。测试集准确率为 `0.5951`、平衡准确率为 `0.5951`、R2为 `0.0745`，高于旧模型记录的 `0.5743` 和 `0.0387`。

执行控制的轨迹预测已经替换为 FilterPy 常速度卡尔曼滤波，初始速度和拟合诊断由 scikit-learn `LinearRegression` 给出。在同一套160条合成轨迹基准上，位置RMSE由 `0.964136` 降为 `0.909958`。关联规则频繁项集挖掘已经替换为 mlxtend `apriori`，领域结果投票、授权门禁和命令结构保持不变。

采用的开源实现：

- [scikit-learn](https://github.com/scikit-learn/scikit-learn)：随机森林与线性回归。
- [FilterPy](https://github.com/rlabbe/filterpy)：卡尔曼滤波。
- [mlxtend](https://github.com/rasbt/mlxtend)：Apriori频繁项集挖掘。

没有引入OR-Tools：当前链路没有提供资源容量、互斥关系、任务时间窗等约束，暂时不存在可被约束求解器合理求解的数学模型。等前置Agent能够稳定给出这些字段后再接入OR-Tools更合理。

评分器现同时兼容当前模型的 `predict_one()` 接口和 scikit-learn 的 `predict()/estimators_` 接口。后续将模型替换为 scikit-learn `RandomForestRegressor` 时，只需更新模型文件；也可以在算法请求的 `params.model_path`、`params.metadata_path` 中指定新模型，不需要修改 Agent 链路。

## 4. 成熟度说明

“成熟开源实现”和“业务模型达到生产精度”是两件事。本次底层实现已经使用 scikit-learn、FilterPy 和 mlxtend，但当前完成度模型仍基于SC2LE代理数据，`0.5951`只能说明比旧代理模型有所改善，不能据此宣称达到真实业务生产精度。上线前仍需用真实标注数据进行独立测试和阈值校准。

## 5. 配置方式

整套系统启动前可在 `.env` 中设置：

```dotenv
EXECUTION_CONTROL_ALGORITHM_PROFILE=medium
CLOSED_LOOP_ALGORITHM_PROFILE=medium
```

单次算法调用也可传入：

```json
{"params": {"profile": "high"}}
```

优先级为：单次请求 `algorithm_profile/profile` > 环境变量 > `medium`。
