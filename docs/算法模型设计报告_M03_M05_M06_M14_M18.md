# 第一章　M03 线性回归：trajectory_linear_predictor

## 1.1 相关原理

### 1.1.1 问题定义与线性运动假设

M03 对应图片中的“线性回归”，在项目中主要实现为 `trajectory_linear_predictor`。它解决的问题是：当目标处于运动状态时，执行控制不能只使用当前观测点，而要估计执行动作真正生效时目标可能到达的位置。

设目标在二维平面中的历史观测序列为：

```text
D = {(t_i, x_i, y_i)}，i = 1, 2, ..., N
```

其中 `t_i` 表示观测时间，`x_i` 和 `y_i` 表示该时刻目标的位置。若在短时间窗口内目标近似匀速运动，则可以分别对 x 方向和 y 方向建立线性模型：

```text
（1-1）
x(t) = v_x * t + b_x
y(t) = v_y * t + b_y
```

式中，`v_x` 和 `v_y` 分别表示目标在 x、y 两个方向上的速度分量，`b_x` 和 `b_y` 是截距。该模型的核心假设是：在预测时间窗口内，目标速度方向和大小不会发生剧烈变化。

项目采用这种模型的原因是它足够稳定、可解释，并且非常适合执行控制中的短时预测场景。相比复杂神经网络，线性回归不依赖大量训练数据，每次只要有当前目标的历史轨迹点，就可以实时拟合。

### 1.1.2 最小二乘估计

对于一组时间序列 `t_i` 和位置值 `x_i`，线性回归通过最小化预测值与真实观测值之间的平方误差来求解斜率和截距：

```text
（1-2）
min Σ(x_i - (v_x * t_i + b_x))^2
```

其闭式解为：

```text
（1-3）
v_x = Σ((t_i - mean(t)) * (x_i - mean(x))) / Σ((t_i - mean(t))^2)
b_x = mean(x) - v_x * mean(t)
```

y 方向同理：

```text
（1-4）
v_y = Σ((t_i - mean(t)) * (y_i - mean(y))) / Σ((t_i - mean(t))^2)
b_y = mean(y) - v_y * mean(t)
```

项目中的 `fit_linear` 函数正是按上述公式计算斜率和截距。它不是调用黑盒训练流程，而是在每次推理时直接根据当前目标轨迹计算模型参数。

### 1.1.3 预测时刻与提前量建模

执行控制中的关键不是预测“下一秒在哪里”，而是预测“准备完成并且动作到达时，目标在哪里”。

因此项目定义两个时间量：

```text
（1-5）
execute_at = last_t + weapon_prep_sec
future_t = last_t + weapon_prep_sec + flight_time_sec
```

其中：

- `last_t` 是最后一个轨迹观测点的时间。
- `weapon_prep_sec` 是执行动作准备时间。
- `flight_time_sec` 是动作发出后到达目标区域的时间。
- `execute_at` 是建议开始执行的时间。
- `future_t` 是动作实际作用到目标时对应的未来时间。

最终瞄准点由下式给出：

```text
（1-6）
aim_x = v_x * future_t + b_x
aim_y = v_y * future_t + b_y
```

该设计使 M03 与执行控制直接衔接：执行控制不再只接收静态坐标，而是接收结合准备时间和飞行时间后的未来瞄准点。

### 1.1.4 模型适用边界

线性回归适用于短时间、近似匀速、轨迹点质量较好的目标。如果目标发生明显机动、急转弯、遮挡后重识别错误或轨迹点时间戳异常，线性模型的预测误差会增大。

因此项目中对输入进行了基本约束：

- 至少需要 2 个历史轨迹点。
- 每个轨迹点必须包含 `t`、`x`、`y`。
- 时间戳必须至少有两个不同值。
- `weapon_prep_sec` 和 `flight_time_sec` 必须存在且非负。
- 输入数值必须是有限数，不能是 NaN 或无穷。

这些约束保证了模型不会在缺失或异常轨迹上静默输出看似合理但实际不可用的瞄准点。

### 1.2.1 项目实现位置

### 1.2.2 输入设计

M03 的核心输入是单个目标的历史轨迹，结构如下：

```json
{
  "track_id": "T-001",
  "history": [
    {"t": 0.0, "x": 100.0, "y": 200.0},
    {"t": 1.0, "x": 112.0, "y": 204.0},
    {"t": 2.0, "x": 124.0, "y": 208.0}
  ],
  "weapon_prep_sec": 2.0,
  "flight_time_sec": 5.0
}
```

字段说明如下：

| 字段 | 类型 | 含义 | 来源 |
| --- | --- | --- | --- |
| `track_id` | string | 目标轨迹编号 | 目标跟踪或数据融合模块 |
| `history` | array | 目标历史轨迹点 | 前置跟踪 Agent、数据融合结果 |
| `history[].t` | number | 观测时间 | 传感器时间戳或融合时间 |
| `history[].x` | number | x 坐标 | 检测/跟踪/定位结果 |
| `history[].y` | number | y 坐标 | 检测/跟踪/定位结果 |
| `weapon_prep_sec` | number | 执行动作准备时间 | 执行控制上下文 |
| `flight_time_sec` | number | 动作飞行或生效延迟 | 执行控制上下文 |

### 1.2.3 输出设计

输出结构如下：

```json
{
  "ok": true,
  "track_id": "T-001",
  "velocity": {"vx": 12.0, "vy": 4.0},
  "aim_point": {"x": 208.0, "y": 236.0},
  "execute_at": 4.0,
  "future_t": 9.0,
  "model": "linear_regression",
  "fit": {
    "r2_x": 1.0,
    "r2_y": 1.0
  }
}
```

| 输出字段 | 含义 | 下游用途 |
| --- | --- | --- |
| `velocity` | 目标速度分量 | 判断目标运动趋势 |
| `aim_point` | 未来瞄准点 | 执行控制使用的目标点 |
| `execute_at` | 建议执行时刻 | 判断控制是否及时 |
| `future_t` | 预测作用时刻 | 解释瞄准点对应的时间 |
| `fit.r2_x/y` | 拟合优度 | 评估线性预测可信度 |

### 1.2.4 运行流程

项目中的运行流程可以概括为：

```text
读取 track.history
  -> 校验轨迹点数量和字段完整性
  -> 按时间 t 排序
  -> 分别取出 ts、xs、ys
  -> 对 x(t) 拟合线性回归
  -> 对 y(t) 拟合线性回归
  -> 根据准备时间和飞行时间计算 future_t
  -> 预测 aim_point
  -> 输出速度、瞄准点、执行时刻和拟合优度
```

如果轨迹点不足，项目不会随便给默认位置，而是返回明确错误：

```json
{
  "ok": false,
  "error": {
    "code": "INSUFFICIENT_HISTORY",
    "message": "track history requires at least 2 points"
  }
}
```

这种设计比使用默认值更合理，因为执行控制是关键链路，宁可暴露输入不足，也不能伪造瞄准点。

### 1.2.5 评估与局限

项目元数据中记录了确定性合成轨迹评估：

| 指标 | 数值 |
| --- | --- |
| 测试样本数 | 160 |
| 匀速样本 | 120 |
| 轻微加速样本 | 40 |
| 位置 MAE | 约 0.52 |
| 位置 RMSE | 约 0.96 |
| P95 误差 | 约 2.17 |

结果说明该模型对匀速目标效果较好，对轻微加速目标也能提供可用近似，但它不是复杂机动目标的最终解决方案。若未来需要处理强机动目标，应引入 Kalman Filter、IMM、LSTM 或轨迹 Transformer 等更复杂模型。

# 第二章　M05 随机森林：threat_priority_random_forest

## 2.1 相关原理

### 2.1.1 问题定义与多特征威胁分类

M05 对应图片中的“随机森林”，项目实现为 `threat_priority_random_forest`。它的任务是根据目标结构化特征判断威胁优先级。

设每个目标的输入特征为：

```text
（2-1）
x = [threat_score, distance_km, speed_mps, asset_value, intel_confidence]
```

模型输出三类概率：

```text
（2-2）
P(priority = low | x)
P(priority = medium | x)
P(priority = high | x)
```

最终优先级为概率最大的类别：

```text
（2-3）
priority = argmax P(c | x), c ∈ {low, medium, high}
```

### 2.1.2 决策树与随机森林

决策树通过一系列条件分裂对样本进行分类。例如：

```text
如果 threat_score > 0.75 且 distance_km < 20，则倾向 high
如果 threat_score 中等且 distance_km 较远，则倾向 medium
否则倾向 low
```

单棵树可解释性强，但容易过拟合。随机森林通过训练多棵树降低这种风险。每棵树在不同的数据子集和特征组合上训练，最终通过投票或概率平均形成集成结果。

对于分类任务，随机森林的概率可以理解为多棵树投票后的比例：

```text
（2-4）
P(c | x) = vote_count(c) / tree_count
```

项目中随机森林包含 160 棵树，最大深度为 8。这个配置在表达能力和稳定性之间做了折中：树太浅会欠拟合，树太深容易记住训练样本。

### 2.1.3 非线性特征组合

威胁优先级不是单指标判断，而是多特征组合判断。比如：

- 威胁分数高但距离很远，可能不是最高优先级。
- 威胁分数中等但距离近、速度快，可能需要优先处理。
- 情报置信度低时，即使威胁值高，也需要更保守或进入复核。
- 涉及高价值资产时，目标优先级可能上升。

随机森林适合这种场景，因为它不要求输入特征之间是线性关系。它可以学习“距离近且速度快”“威胁高但情报不可靠”等组合条件。

### 2.1.4 类别概率与置信度

项目不仅输出 `priority`，还输出 `class_probabilities` 和 `confidence`。

例如：

```json
{
  "priority": "high",
  "confidence": 0.91,
  "class_probabilities": {
    "low": 0.02,
    "medium": 0.07,
    "high": 0.91
  }
}
```

其中 `confidence` 就是被选中类别的概率。它不是目标真实威胁的绝对真值，而是模型在当前特征和训练分布下对该类别的支持程度。

## 2.2 算法设计

### 2.2.1 项目实现位置

| 模块 | 路径 | 职责 |
| --- | --- | --- |
| 随机森林推理 | `commander/services/a2a_algorithms_common/threat_priority_random_forest.py` | 加载模型、校验输入、输出威胁优先级 |

### 2.2.2 输入特征设计

M05 输入是目标列表，每个目标必须包含 `target_id` 和五个数值特征：

```json
{
  "targets": [
    {
      "target_id": "T-001",
      "threat_score": 0.86,
      "distance_km": 12.5,
      "speed_mps": 280.0,
      "asset_value": 0.75,
      "intel_confidence": 0.82
    }
  ]
}
```

特征含义如下：

| 特征 | 取值范围 | 含义 | 典型来源 |
| --- | --- | --- | --- |
| `threat_score` | 0 到 1 | 目标自身威胁程度 | 规则评估、目标类型识别、前置威胁评估 |
| `distance_km` | 0 到 10000 | 目标距离 | 定位、传感器、轨迹融合 |
| `speed_mps` | 0 到 5000 | 目标速度 | 跟踪模块、轨迹预测模块 |
| `asset_value` | 0 到 1 | 目标关联资产价值 | 任务规划、资源上下文 |
| `intel_confidence` | 0 到 1 | 情报可信度 | 检测置信度、M14 校验、融合置信度 |

项目中 `_finite_feature` 对每个特征进行范围校验，拒绝布尔值、非数字、NaN、无穷值和越界值。这样可以保证模型输入空间与训练元数据一致。

### 2.2.3 推理与排序设计

M05 的推理流程如下：

```text
接收 targets
  -> 校验 targets 非空且数量不超过 10000
  -> 校验每个 target_id
  -> 按元数据中的 feature_order 构造特征矩阵
  -> 加载 joblib 随机森林模型
  -> 调用 predict_proba
  -> 生成 low/medium/high 概率
  -> 选择概率最高类别作为 priority
  -> 可选按 high、medium、low 和置信度排序
```

输出示例：

```json
{
  "priorities": [
    {
      "target_id": "T-001",
      "priority": "high",
      "confidence": 0.91,
      "class_probabilities": {
        "low": 0.02,
        "medium": 0.07,
        "high": 0.91
      }
    }
  ],
  "target_count": 1,
  "model_version": "1.0.0",
  "assessment_scope": "repository_reference_model",
  "model_runtime": {
    "backend": "sklearn_random_forest",
    "used": true
  }
}
```

如果设置 `sort_descending = true`，结果会按优先级和置信度排序，排序规则为：

```text
high > medium > low
同等级下 confidence 越高越靠前
仍相同则按 target_id 稳定排序
```

### 2.2.4 模型发布与完整性校验

项目在加载模型前会校验：

- 模型文件是否存在。
- 元数据文件是否存在。
- 元数据中的 `model_version` 是否为 `1.0.0`。
- 模型文件 SHA-256 是否与元数据记录一致。

如果校验失败，模型不会继续推理，而是抛出错误。这一点很重要，因为随机森林属于离线训练后部署的模型，线上必须确保使用的是经过记录和批准的模型文件，而不是未知来源或被替换的文件。

### 2.2.5 ONNX 版本设计

项目还提供了 ONNX 版本：

```text
commander/examples/threat_priority_random_forest_onnx/1.0.0/
```

ONNX 版本记录：

- 模型族：`onnx_ml_random_forest_classifier`
- 树数量：160
- 特征顺序：与 sklearn 版本一致
- 类别顺序：`low`、`medium`、`high`
- 与 sklearn 概率最大绝对误差：约 `1.429e-06`

这说明 ONNX 版主要用于部署兼容，而不是改变算法逻辑。它可以在不安装 sklearn 的环境中运行同一个威胁优先级模型。

# 第三章　M06 传统神经网络：supcon_meta_classifier

## 3.1 相关原理

### 3.1.1 问题定义与嵌入分类

M06 对应图片中的“传统神经网络”，项目实现为 `supcon_meta_classifier`。它的任务是对前置融合后的目标嵌入向量进行类别判断。

输入不是原始图像或原始文本，而是前置多模态编码与融合模块输出的 `fused_embeddings`：

```text
（3-1）
e_i = Fusion(sensor/image/text/track features)
```

模型根据嵌入向量判断目标类别：

```text
（3-2）
y_i ∈ {friendly, neutral, hostile, unknown}
```

这种设计把“多源数据怎么编码”与“目标类别怎么判断”分开。M06 只处理统一向量，不关心向量最初来自图像、雷达、文本还是其他传感器。

### 3.1.2 有监督对比学习

`supcon` 指 Supervised Contrastive Learning，即有监督对比学习。它的目标是在向量空间中形成更清晰的类别结构：

```text
同类样本距离更近
异类样本距离更远
```

对于一个样本 i，同类样本集合记为 P(i)，其他样本作为负样本。有监督对比损失可以写成：

```text
（3-3）
L_i = - 1/|P(i)| * Σ log exp(sim(z_i, z_p)/τ) / Σ exp(sim(z_i, z_a)/τ)
```

其中：

- `z_i` 是样本嵌入经过模型投影后的表示。
- `sim` 是相似度函数，常用余弦相似度或点积。
- `τ` 是温度系数。
- `P(i)` 是与样本 i 同类别的正样本集合。

该损失会让同类目标聚集到一起，让不同类目标分开，从而提升少样本或边界样本的分类稳定性。

### 3.1.3 原型分类与温度缩放

项目中的 M06 可以理解为“对比学习表示 + 原型分类”。训练后，每个类别在向量空间中形成一个代表性原型。新目标输入后，模型计算它与各类别原型的相似度：

```text
（3-4）
s_c = sim(z, prototype_c)
```

再通过 softmax 得到类别概率：

```text
（3-5）
P(c | z) = exp(s_c / τ) / Σ exp(s_k / τ)
```

项目中默认温度系数为：

```text
τ = 0.07
```

温度越小，概率分布越尖锐；温度越大，概率分布越平滑。较小的温度会让模型在类别相似度差异明显时输出更高置信度。

### 3.1.4 与普通 MLP 分类的区别

普通 MLP 分类器通常直接学习：

```text
embedding -> linear/mlp -> class logits
```

M06 的特点是强调嵌入空间结构。它不仅追求分类正确，还希望同一类目标在表示空间中更接近。这对 A2A 场景有意义，因为上游多模态融合可能来自不同传感器，直接分类容易受模态差异影响，而对比学习有助于把语义相同的目标拉到同一类区域。

# 第四章　M14 可解释 AI：edl_evidential_verifier

## 4.1 相关原理

### 4.1.1 问题定义：检测结果可信性验证

M14 对应图片中的“可解释 AI”，项目实现为 `edl_evidential_verifier`。它的任务是对前置检测结果进行可信性验证。

目标检测模型通常输出检测框、类别和置信度。但检测置信度并不等于最终可信度，原因包括：

- 检测框可能定位不准。
- 检测器可能在陌生场景中过度自信。
- 图像质量、遮挡、烟雾、噪声会影响结果。
- 检测置信度不能直接说明模型是否缺乏证据。

因此 M14 不只判断检测是否通过，还输出不确定性，用于决定：

```text
verified：可信，进入后续链路
rejected：不可信，拒绝进入后续链路
manual_review：不确定，需要人工复核
```

### 4.1.2 证据深度学习

EDL 是 Evidential Deep Learning，中文可称为证据深度学习。普通分类模型输出类别概率，而 EDL 先输出每个类别的证据强度：

```text
（4-1）
e_c >= 0
```

然后将证据转换成 Dirichlet 分布参数：

```text
（4-2）
alpha_c = e_c + 1
S = Σ alpha_c
```

类别概率为：

```text
（4-3）
P(c) = alpha_c / S
```

不确定性可以根据总证据强度估计：

```text
（4-4）
uncertainty ≈ K / S
```

其中 K 是类别数量。证据越多，S 越大，不确定性越低；证据越少，S 越小，不确定性越高。

### 4.1.3 Epistemic 与 Aleatoric 不确定性

项目中 M14 关注两类不确定性：

| 不确定性 | 中文解释 | 典型原因 |
| --- | --- | --- |
| `epistemic_uncertainty` | 模型认知不确定性 | 训练数据覆盖不足、陌生场景、证据不足 |
| `aleatoric_uncertainty` | 数据噪声不确定性 | 图像模糊、遮挡、传感器噪声、目标本身不清晰 |

这两者含义不同：

- Epistemic 高，说明模型“不太懂这个样本”。
- Aleatoric 高，说明样本本身“看起来就很难判断”。

可解释 AI 的价值就在这里：它不只告诉你结论，还告诉你这个结论有多可靠，为什么需要复核。

### 4.1.4 决策阈值与人工复核

项目 ONNX 元数据中记录的策略包括：

```text
verified_probability_threshold = 0.5
maximum_epistemic_uncertainty = 0.45
manual_review_margin = 0.08
```

可以理解为：

```text
如果 verified 概率足够高，且 epistemic 不确定性不高，则 verified
如果 verified 概率明显低，则 rejected
如果概率接近阈值，或 epistemic 不确定性过高，则 manual_review
```

该设计避免了检测器“高置信但证据不足”的风险，让后续威胁评估、跟踪、毁伤确认和执行控制建立在更可靠的感知结果上。

| `review_required` | 是否需要人工复核 |

这使得 M14 不只是一个二分类器，而是一个“带解释和复核策略的检测可信性判断器”。

# 第五章　M18 差分/变化检测：siamese_mask2former_damage 与 xbd_damage_assessor

## 5.1 相关原理

### 5.1.1 问题定义：前后时相变化检测

M18 对应图片中的“差分/变化检测”，项目中对应两条实现：

- `siamese_mask2former_damage`
- `xbd_damage_assessor`

它们共同解决的问题是：同一区域在行动前和行动后相比，是否出现明显变化或毁伤。

基本输入可表示为：

```text
（5-1）
I_pre = 行动前图像
I_post = 行动后图像
R = 目标区域或建筑多边形
```

模型输出：

```text
（5-2）
damage_probability 或 damage_score
damage_result ∈ {damaged, no_damage}
```

### 5.1.2 差分检测不是简单像素相减

最直观的变化检测是：

```text
（5-3）
Diff = |I_post - I_pre|
```

但真实场景中不能只靠像素差，因为前后图像可能存在：

- 光照变化。
- 拍摄角度变化。
- 传感器噪声。
- 图像配准误差。
- 遮挡和阴影。
- 地表背景自然变化。

因此项目设计中引入了更稳健的图像特征、区域特征和神经网络特征，而不是简单地把像素差作为最终结论。

### 5.1.3 Siamese 网络与变化分割

Siamese 网络也叫孪生网络，它使用两个结构相同或共享参数的分支分别处理前后图像：

```text
（5-4）
F_pre = Encoder(I_pre)
F_post = Encoder(I_post)
F_diff = Compare(F_pre, F_post)
```

然后通过分割头输出变化区域：

```text
（5-5）
Mask = SegmentationHead(F_diff)
```

项目中的 `siamese_mask2former_damage` 即属于这种思路。Mask2Former 类型结构适合输出 mask，也就是不仅判断有没有毁伤，还能定位毁伤区域在哪里。

### 5.1.4 xBD 毁伤评估

xBD 是面向灾害和建筑毁伤评估的数据与任务体系。项目中的 `xbd_damage_assessor` 更偏向结构化毁伤分类：

```text
前后图像 + 目标 polygon
  -> 提取 ROI 特征
  -> 生成手工特征
  -> 可选提取 CNN embedding
  -> 分类器输出 damage_probability
```

项目元数据中记录的模型来源为：

```text
xbd_handcrafted_plus_resnet18_lr
```

可以理解为：

- `handcrafted`：使用人工设计的统计、纹理、形状、差异特征。
- `resnet18`：使用 CNN 提取更高层视觉特征。
- `lr`：使用逻辑回归类分类器输出毁伤概率。

| 特征类型 | 维度 | 作用 |
| --- | --- | --- |
| 手工特征 | 31 | 表达 ROI 区域的统计、纹理、几何和前后差异 |
| CNN 特征 | 1536 | 表达 ResNet18 对前后 ROI 图像的深层视觉理解 |
| 总特征 | 1567 | 作为分类器输入 |

手工特征适合捕捉明确、可解释的变化，例如亮度差、纹理差、区域统计变化；CNN 特征适合捕捉人工特征难以表达的复杂视觉模式。两者结合可以兼顾可解释性与表达能力。

### 5.2.5 毁伤概率与阈值判定

模型输出毁伤概率：

```text
（5-6）
p_damage = model(feature_vector)
```

项目元数据中的阈值为：

```text
decision_threshold = 0.645
```

最终判定规则是：

```text
（5-7）
if p_damage >= 0.645:
    damage_result = "damaged"
else:
    damage_result = "no_damage"
```

因此，`damage_probability` 是连续概率，`damage_result` 是阈值化后的离散结论。闭环评估更适合同时保留两者：概率用于衡量程度，离散结论用于判断任务是否完成。

### 5.2.6 缺失输入处理

xBD assessor 对关键输入缺失会返回 `insufficient_data`，例如：

- 特征模式下缺少 `handcrafted_features`。
- 图像模式下缺少 `polygon`。
- 图像模式下 polygon 不合法。
- ROI 无法提取或 CNN embedding 无法生成。

示例：

```json
{
  "assessment_status": "insufficient_data",
  "missing_fields": ["polygon"],
  "damage_probability": null,
  "damage_label": null,
  "decision_threshold": 0.645
}
```

这种处理方式比默认给一个毁伤概率更合理，因为毁伤评估直接影响闭环是否认为任务完成，不能在关键证据缺失时伪造判断。

# 第六章　五个算法在 A2A 链路中的协同关系

## 6.1 端到端链路位置

这五个算法可以组成一条从感知到执行的关键链路：

```text
目标检测结果
  -> M14 EDL 检测可信性验证
  -> M06 SupCon 目标属性分类
  -> M18 变化检测/毁伤评估
  -> M05 随机森林威胁优先级判断
  -> M03 线性轨迹预测
  -> 执行控制与闭环评估
```

每个模型承担的角色不同：

| 环节 | 算法 | 输入 | 输出 | 对下游的意义 |
| --- | --- | --- | --- | --- |
| 感知校验 | M14 | detections、bbox、confidence、damage_score | verified/rejected/review | 过滤不可靠检测 |
| 目标理解 | M06 | fused_embeddings | 目标类别和置信度 | 判断目标属性 |
| 效果确认 | M18 | pre/post 图像、polygon、特征 | damage_probability、damage_result | 判断是否发生毁伤 |
| 威胁排序 | M05 | threat_score、distance、speed、asset、intel | low/medium/high | 决定优先级 |
| 执行预测 | M03 | track history、准备时间、飞行时间 | aim_point、execute_at | 支持执行控制 |

## 6.2 与闭环评估的关系

闭环评估需要判断任务是否真的完成，而不是只看动作是否发出。这五个算法分别提供不同证据：

| 闭环评估问题 | 对应算法 | 可使用输出 |
| --- | --- | --- |
| 检测结果是否可信 | M14 | `verified_detections`、`epistemic_uncertainty` |
| 目标属性是否明确 | M06 | `label`、`confidence` |
| 目标是否已毁伤 | M18 | `damage_probability`、`damage_result` |
| 当前威胁是否仍高 | M05 | `priority`、`class_probabilities.high` |
| 执行是否及时 | M03 | `execute_at`、`future_t`、`aim_point` |

因此，闭环评估不应依赖单一模型，而应综合来自感知可信性、目标属性、毁伤结果、威胁压力和执行预测的多源证据。

## 6.3 项目设计原则

当前设计体现了几个原则：

### 6.3.1 不用默认值伪造关键结果

对于关键输入缺失的情况，项目倾向于返回错误或 `insufficient_data`，而不是生成一个默认分数。这一点在 M03 和 M18 中尤其明显：

- M03 缺少轨迹点时返回 `INSUFFICIENT_HISTORY`。
- M03 缺少准备时间或飞行时间时返回 `MISSING_PREDICTION_HORIZON`。
- M18 缺少 polygon 或特征时返回 `insufficient_data`。

这保证了闭环评估不会建立在伪造证据上。

### 6.3.2 模型输出保留概率和解释信息

M05、M06、M14、M18 都尽量保留概率或置信度：

- M05 输出三类威胁概率。
- M06 输出目标类别置信度。
- M14 输出证据、不确定性和复核队列。
- M18 输出毁伤概率和阈值。

这样做的好处是：下游不仅知道结论，还能知道结论的强弱和可信程度。

### 6.3.3 算法和服务解耦

项目通常把算法实现、服务入口、模型元数据和 Agent Skill 分开：

```text
算法核心函数
  -> Agent Skill 或 service predictor
  -> HTTP / A2A 服务入口
  -> 上层调度和闭环评估
```

这种结构便于替换模型。例如 M05 可以从 sklearn 版本切换到 ONNX 版本，M06 和 M14 也可以通过 ONNX 进行部署，而上层链路不需要改变业务语义。

## 6.4 汇报用总结

可以用下面这段作为汇报口径：

> 本项目中，图片所列 M03、M05、M06、M14、M18 分别落在执行预测、威胁排序、目标分类、检测验证和毁伤评估五个位置。M03 使用最小二乘线性回归，根据目标历史轨迹预测执行生效时的未来瞄准点；M05 使用随机森林综合威胁值、距离、速度、资产价值和情报置信度，输出 low/medium/high 威胁优先级；M06 使用有监督对比学习和原型分类，对融合嵌入向量进行 friendly、neutral、hostile、unknown 分类；M14 使用证据深度学习，把检测结果转成概率、证据和不确定性，从而决定通过、拒绝或人工复核；M18 使用前后时相变化检测和 xBD 毁伤评估，根据图像差异、手工特征和 CNN 特征输出毁伤概率。五个算法共同支撑项目从感知可信性、目标理解、威胁评估到执行控制和闭环优化的完整链路。
