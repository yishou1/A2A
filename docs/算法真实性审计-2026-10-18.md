# 算法真实性与可用性审计（2026-10-18）

此报告是修复前快照（当时 29 项活动）。后续通用软件修复、18 项活动目录及剩余问题见 [修复记录](算法真实性修复记录-2026-10-18.md)。原快照 JSON 已另存为 `.runtime/algorithm-audit-readiness-before-repair.json`。

结论：当前部署不能认定为“全部算法均能正常、正确、真实使用”。

这是本机正在运行的 Docker 部署的审计快照。检查覆盖 43 个算法包；当前活动目录为 29 项，另有 14 项未在活动目录中。包静态校验为 43 项通过、27 条警告；静态通过不代表执行了真实算法。

## 核对范围

所有包均检查了算法卡、契约/样例文件、活动目录，以及可用的 HTTP health/metadata、进程的 Mock 配置、模型文件及来源信息。仅收集允许的执行模式环境变量，不导出凭据。增加了通用算法的样例调用和隔离注册表调用验证，没有重启业务容器、修改当前活动注册表、切换仿真或更新远端分支。

涉及武器分配、攻击决策、火控的模块仅做软件与部署状态核查，未启用或调优作战功能。未用有标注的代表性数据集对各模型重新做正确性/精度认证。因此“未验收”不能算作通过，也不能据此断言算法一定错误。

## 主要问题

1. 当前构建缓存为 `ALGOLIB_WITH_ONNXRUNTIME:BOOL=OFF`，源码中的 stub 分支也与实际返回一致。11 个其他原生 ONNX 包没有进入活动目录；唯一已激活的 onnx_text_classifier 仍走 stub。
2. TIA 的 `tia_model_loaded()` 在 Mock 模式直接返回 True；通用 HTTP 工厂在没有模型检查回调时也默认 True。因此 model_loaded 字段不总是“权重已实际加载”的证据。
3. 权重目录分裂：启动的是 commander 服务，部分新增权重仅存在于 algorithmrepo。GAN 和图关系模型在当前服务读取的目录中缺失。
4. MOTR 跟踪、MARL 路由缺少相应训练权重。共享 `_load_state_dict()` 在文件缺失时直接返回新建模块；相关调用者可能得到随机初始化网络。不能直接把全局 TIA_USE_MOCK 改成 0 就称为真实可用。
5. 部分 CSV 在 Windows 工作树中为 CRLF，而元数据按 LF 字节计算哈希。原始哈希不一致的样本数据在规范化 LF 后吻合；这是复现/部署问题的证据，不是文件被篡改的证据。
6. EDL、Mamba、SupCon、MARL-PPO 等已有权重元数据主要来自合成或参考数据评估。文件存在、确实执行了训练模型、真实场景精度达标是三个不同的结论。
7. 独立 SynapseRAG 服务和名为 synapse_rag_retriever 的 TIA 子算法需要分别核查；后者当前仍在 Mock 模式。
