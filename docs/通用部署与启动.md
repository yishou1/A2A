# 通用部署与启动

适用于 Windows 10/11 x64。入口根据自身位置定位仓库，支持中文、空格和不同盘符；不依赖开发者的 Conda 环境、Python 路径或 `.runtime` 中的旧脚本。

## 另一台设备需要准备什么

1. 安装 Docker Desktop，启用 Linux 容器及其 WSL2 后端。
2. 建议宿主机至少 16 GB 内存，为 Docker 分配至少 12 GB；预留至少 40 GB 磁盘空间。
3. 复制当前完整项目，或获取包含这些启动脚本的仓库版本。必须保留源码、`compose*.yaml`、模型及知识库索引；不需要复制本机 `.venv`、`node_modules`、编译目录和 `.runtime`。
4. 首次启动需联网下载镜像、依赖、Qwen 对话/向量模型及检索模型。启动器不自动安装 Docker 或更改系统配置。

## 双击入口

| 文件 | 功能 |
| --- | --- |
| `检查部署环境.bat` | 检查 Docker、Linux 容器、可用内存、必要文件和宿主端口，不下载或启停容器 |
| `启动项目.bat` | 构建、准备模型、启动完整链路，全部健康后打开网页 |
| `查看项目状态.bat` | 显示容器状态并检查完整业务后端，未就绪时返回非零退出码 |
| `检查算法真实性.bat` | 只读核查算法模式和依赖，存在 Mock、stub、不可用或未验证项时返回失败；不进行精度认证 |
| `运行通用算法验收.bat` | 使用已随项目交付的公开植物/化学数据测试聚类与联邦平均，保存独立报告；不代表全库验收 |
| `停止项目.bat` | 停止当前目录对应的 Compose 项目，保留模型、索引与运行数据卷 |

默认使用 CPU，可在没有 GPU 的设备上运行。启用 NVIDIA GPU 时，在终端执行 `启动项目.bat -Gpu`，需要 Docker 的 NVIDIA GPU 支持；GPU 检查失败时不会悄悄切换成成功状态。

`启动融合界面.bat` 仍只用于本机算法界面开发。完整项目请使用 `启动项目.bat`；两个入口默认占用同一端口，不要同时运行。端口冲突时通用启动器会报错，不会擅自结束其他程序。

## 完整链路包含什么

- AMOS 仿真页面与算法管理前端；
- Commander、Gateway、七个 Agent、AlgoLib 和脚本管理的算法服务；
- Ollama/Qwen 对话及向量模型、SynapseRAG 知识检索；
- Nacos 注册发现、演示用 auth-mock 认证服务。

AMOS 的图片检测调用通过容器名 `a2a-core:9020` 访问核心容器中的检测服务，不使用宿主 Conda 环境；默认感知模式仍以下面的说明为准。
检测服务在容器模式监听 `0.0.0.0`，原生模式默认只监听回环地址；`RTDETR_BIND_HOST` 可显式覆盖。启动及状态检查会验证跨容器检测服务的健康状态和模型就绪标志，避免只看到网页就报告整个链路可用。

启动成功后访问 `http://127.0.0.1:5000/`，算法管理台位于 `/algolib/algorithms`。只有完整健康检查通过才打印 `Ready` 并打开网页，不会自动执行剧本或授权模拟攻击。

当前 Compose 配置使用真实 Qwen 规划，图片检测默认使用真实 97 类 RT-DETR。`RTDETR_USE_MOCK=0` 单独控制图片检测，不受其他 TIA 算法的 `TIA_USE_MOCK=1` 影响。启动检查会校验服务元数据中的真实模式和 97 类数量；AMOS 图片检测接口拒绝把 Mock 输出当成识别结果。

RT-DETR 权重没有提交到 Git。换设备时必须另外携带发布包，先运行 `algorithmrepo/scripts/install_rtdetr_release_bundle.ps1 -BundlePath <发布包目录>`，或在复制完整项目时保留 `algorithmrepo/models/checkpoints/battlefield_rtdetr.pt`。缺失时启动器会提前报错，不能只克隆源码就获得真实检测。MOTR、ODConv 等其他专用感知模型仍需各自的权重与配置；部分算法保留演示模式。

真实推理不代表类别与目标数量已经验证准确。页面展示权重的原始预测，当前模型可能把货船误判为驱逐舰，也可能漏检远处的小船；应使用有标注的图片评估模型，不能用场景对象名称替换预测来制造准确结果。

## PowerShell 参数

从项目目录执行，路径不需要改成某台机器的绝对路径：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\project.ps1 -Action Check
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\project.ps1 -Action Start
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\project.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\project.ps1 -Action Logs
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\project.ps1 -Action Stop
```

可选启动参数：

```powershell
# 替换被占用的端口，关闭自动打开浏览器；后续重启仍需使用相同端口参数。
.\scripts\project.ps1 -Action Start -AmosPort 5001 -GatewayPort 8031 -NoBrowser

# NVIDIA GPU，或延长容器健康等待时间。
.\scripts\project.ps1 -Action Start -Gpu -StartupTimeoutSeconds 7200
```

也可在本机 `.env` 中配置 `AMOS_HOST_PORT` 和 `A2A_GATEWAY_HOST_PORT`，由 Compose 读取；不要把密钥或个人 `.env` 分发给其他设备。脚本会发现 PATH 中或 Docker Desktop 标准安装目录中的 Docker；自定义安装位置可通过环境变量 `A2A_DOCKER_PATH` 指定 `docker.exe`。

## 失败与恢复

- 找不到 Docker：先安装 Docker Desktop；安装后旧终端未更新 PATH 时也会尝试标准安装目录。
- Docker 未启动：启动入口会尝试打开 Desktop；检查入口只报告未就绪，不启动它。
- 内存不足或容器类型为 Windows：先调整 Desktop 配置，再启动。
- 端口占用：停止对应原生服务，或更换上述宿主端口。
- 文件缺失、为空或仍是 Git LFS 指针：补齐完整源码/数据，必要时执行 `git lfs pull`。
- 网络、镜像构建、模型下载或运行健康失败：启动返回非零退出码，不报告成功；使用 `-Action Logs` 查看原因。修复后重新执行启动入口，已下载模型保留在命名卷中。

容器与数据卷名称按仓库绝对路径派生。同目录重复启动复用原数据；移动目录或换设备会形成独立部署，不自动迁移旧容器卷。迁移已有运行数据时需要另外备份与恢复 Docker 卷。
