# 算法真实性修复记录（2026-10-18）

已完成通用软件层的真实性检查和错误处理修复，尚未实现“43 个算法全部真实、正确可用”。缺失权重、未启用的真实 ONNX 后端、模型适用范围及真实数据精度问题仍然存在。涉及武器分配、攻击决策或火控的作战功能未启用或增强。

## 当前运行中的变化

- 10 个 TIA Mock 服务明确报告 `inference_mode=mock`、`status=mock`、`model_loaded=false`、`ready_for_real=false`；模拟接口仍可用于明确的演示，但不再冒充已加载真实模型。
- 已备份本地注册表，并将这 10 个 Mock 条目和 1 个 ONNX stub 条目停用。活动目录从 29 项变为 18 项。**18 项活动条目也不等于 18 项通过了真实场景精度验收。**依赖被停用算法的原演示流程会明确失败，不能再依赖模拟结果继续执行。
- 聚类和联邦平均标记为 `deterministic`，表示执行实际数学算法，不声称加载了训练模型。它们在严格调用要求下通过了 HTTP 与隔离注册表 AlgoLib 两条路径的样例验证。
- 现有检测服务仅重载通用接口检查；模型、类别数和计算配置保持原状。健康接口确认真实模式已就绪，未做分类精度增强。
- 仿真运行标识保持 `run-a30d686f80c0`，仿真时刻保持 `5411.1586265563965` 秒。没有切换或重置场景，没有更新远端分支。

## 验证结果

- 19 项 Python 检查通过：13 项通用接口/权重完整性测试和 6 项既有模型就绪回归检查。
- 40 项通用 C++ 回归测试通过，包括严格调用拒绝 stub 及健康状态披露。
- 聚类、联邦平均两项严格验收通过，均包含 HTTP 和 AlgoLib 调用路径。使用隔离注册表，没有重新激活其他业务算法。
- 新镜像内的普通文本分类严格调用明确返回 `ONNX_RUNTIME_ERROR`，原因为当前仅有 stub 后端；这是预期的拒绝行为，不是模型可用性通过。
- 服务基础链路健康检查通过；完整算法真实性检查仍失败，退出码为 1，明确保留剩余问题。

测试所需的目录配置曾在隔离 C++ 测试容器中缺失；指定与项目一致的函数目录配置后，40 项全部通过。没有修改业务代码来绕过该测试环境问题。
