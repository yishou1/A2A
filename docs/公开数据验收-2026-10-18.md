## 固定的标准

`acceptance/generic_criteria.json` 在首次测试前固定，SHA-256 为 `6c3414db69693e3f12526fae3a6e2a70212e78abd1fe2254c4d5d69e64189eff`。修复和重跑过程中该值保持不变。标准为本轮提出的暂定工程基准，不是用户批准的生产 SLA。

- K-Means：收敛、成员/中心正确、惯性不超过独立 scikit-learn 参考的 1.1 倍、外部标签 ARI 至少 0.5、相同输入重放一致。
- DBSCAN：与参考实现的分区 ARI 接近 1，噪声集合相同，成员/中心与非退化检查通过。没有把这些检查当成类别恢复精度认证。
- FedAvg：公开测量数据产生三个本地岭回归参数，对照独立 NumPy 的按样本量加权平均，绝对/相对误差容限均为 1e-10；另外核对张量形状、参与数量与权重和。
- 调用链：HTTP、隔离注册表 AlgoLib 均使用 require_real，明确披露 deterministic 模式，检查无效输入、路径输出一致性和暂定单次 5 秒预算。

ARI 是分区一致性指标，不是分类准确率，解释可参见 [scikit-learn 官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.adjusted_rand_score.html)。

Wine 上 DBSCAN 只产生一个簇，虽然与相同参数的参考实现一致，但不能据此推荐它完成 Wine 类别恢复。没有为了改进这个分数临时调参、改标签或降低阈值。

FedAvg 的公开数据留出回归误差只作为描述性观察，不作为联邦训练收敛、隐私保护或生产模型精度证明。公开数据用于通用算法的数学检查，没有训练或增强作战模型。

本轮暖态小请求中，HTTP 单次最多约 51.95 ms，AlgoLib 单次最多约 78.67 ms。环境为 Python 3.11.16、NumPy 2.4.6、scikit-learn 1.7.2。这些数值不代表冷启动、并发、大规模输入或其他设备的性能。

## 检查发现并修复的问题

1. 首轮两个有效边界测试漏填了契约要求的 round_id，导致 AlgoLib 拒绝；首轮失败报告保留在 `.runtime/public-data-acceptance-latest/`。修正了测试输入，并增加明确的缺 round_id 反例。
2. 同时发现 HTTP 直接接口原来会接受缺少 round_id 的请求，与 AlgoLib 的输入契约不一致。两个通用服务现在按自身 input.schema.json 做校验，非法输入在计算前返回错误；没有修改数值计算算法或模型权重。使用标准 [JSON Schema 验证接口](https://python-jsonschema.readthedocs.io/en/stable/validate/)，已补充项目依赖。
3. 维护重载触发了现有 PID 守护竞态，导致核心容器自动重启。修复了主动停止前撤下 PID、原子写入 PID 以及守护检查时复核 PID 文件的逻辑。两个隔离进程测试确认主动维护不会误判，真正的意外退出仍被发现。

最终镜像通过 17 项通用 Python 回归检查。所有 43 个包的静态结构检查也通过，但仍有 27 条警告；这部分只能证明包结构/契约文件符合现有检查，不能替代真实模型验收。

## 运行状态与剩余限制

核心服务已恢复为新镜像，恢复了维护前已活动的原检测条目，先核对了原有模型 SHA-256、真实模式与 97 类身份。没有安装替代检测权重或做分类精度优化。完整基础服务链路健康检查通过。

当前活动条目仍为 18 项，Mock/stub 保持停用；其余活动服务没有因健康接口正常就被标为真实模式或精度合格。仿真仍为 `run-a30d686f80c0`，时刻仍为 `5411.1586265563965` 秒。远端分支没有更新。

整体真实性检查仍返回失败。缺少权重、真实原生 ONNX 后端、目录交付不一致和未验证执行模式的问题没有被这两套公开数据解决。另确认 onnx_text_classifier 的算法卡本身把它定义为 constant-logit 集成夹具；它不能因文件存在或 Python ONNX 能运行就被算作训练好的语义分类模型。

涉及目标判定、威胁排序、攻击决策、武器或火控效能的模块没有补充训练数据、调参或增强能力。
